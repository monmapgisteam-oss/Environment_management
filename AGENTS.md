# Repository Guidelines

## Project Structure & Module Organization

This is a private report submission and evaluation system, split into three folders that ship as Docker containers behind an nginx proxy (`docker-compose.yml`, `nginx/default.conf`).

- `backend/`: Fastify API (TypeScript). It holds every secret and is the only part that talks to the private ArcGIS feature service `Hosted/Tailan` (tables `tailan_<model>`, files as attachments of `tailan_upload`).
  - `src/server.ts`: the server.
  - `src/routes/**/route.ts`: API handlers. They take a Web `Request` and return a `Response`; `src/http/adapter.ts` runs them, and `src/http/next.ts` supplies `NextResponse`, `cookies()` and `headers()`. `src/routes/index.ts` is generated by `npm --prefix backend run routes`.
  - `src/views/<area>/`: page views, the data each frontend page renders.
  - `src/lib/`: `auth`, `db` (repository engine, ArcGIS client, schema, storage), `reports`, `map`.
  - Also `scripts/` and `tests/`. Alias: `@/` = `backend/src`.
- `frontend/`: Next.js 16 App Router UI only, with no secrets and no database access. Alias: `@/` = `frontend/`.
  - Each portal (`app/sender`, `app/reviewer`, `app/evaluator`, `app/admin`) has a `layout.tsx`. It checks the role through `@/lib/auth` and renders `components/layout/AppShell.tsx`; pages render only their `<main>`.
  - Server pages get their data with `loadView(...)` from `@/lib/api/server`.
  - Reusable UI lives in `components/`, grouped by feature folder.
  - Browser helpers live in `lib/`; static files in `public/`.
- `shared/`: pure TypeScript used by both sides, imported as `@shared/...`:
  - record types (`db/models.ts`, `db/types.ts`);
  - roles (`auth/roles.ts`) and sidebar menus (`nav.ts`);
  - constants and utils;
  - pure report helpers (`reports/`);
  - the page-view contract (`views/`).

  It must not import from `backend/` or `frontend/`.

## Build, Test, and Development Commands

- `npm run install:all`: install backend and frontend dependencies.
- `npm run dev:backend` / `npm run dev:frontend`: local servers on ports 4000 and 3000 (the frontend forwards `/api` to the backend). Backend values come from `.env.local` at the root.
- `npm run lint`: type-check backend and frontend (`tsc --noEmit`).
- `npm test`: backend tests (`backend/tests`) and frontend tests (`frontend/tests`).
- `npm run build`: backend bundle (`backend/dist/server.mjs`) and Next.js standalone build.
- `docker compose up -d --build`: run proxy, frontend and backend; secrets come from `.env`.
- `npm run setup`: create the core report types and every category's scoring sheets in a fresh ArcGIS service (safe to re-run).
- `npm run arcgis:provision`: add tables, fields, and indexes from `backend/src/lib/db/schema.json` that the ArcGIS service lacks (`-- --dry-run` to list them).

## Coding Style & Naming Conventions

Use TypeScript with `strict` mode enabled. Prefer React function components and keep component files in PascalCase, for example `StatusBadge.tsx` or `ReportTable.tsx`. Utility modules use camelCase filenames, such as `reviewedLocations.ts`. Follow the existing two-space indentation style, Tailwind utility classes for styling, and small typed props objects for components.

To add a page that needs data:
1. Declare the view's data type in `shared/views/<area>.ts`.
2. Implement it with `defineView` in `backend/src/views/<area>/` and add it to that folder's `index.ts`.
3. Call `loadView('<area>/<page>', { params, query })` in the page.

## Testing Guidelines

Tests use the Node test runner; `.ts`/`.tsx` files load through each side's `register-typescript.cjs`. Name files after the behavior, such as `sidebar-nav.test.cjs`. Backend tests cover handlers, views and shared helpers. Frontend tests render components. Also validate changes with `npm run lint`, `npm run build`, `docker compose up -d --build`, and targeted manual checks through the relevant role flow.

## Commit & Pull Request Guidelines

Recent commit messages are short and informal, so keep new commits concise but descriptive, for example `fix report return flow` or `add evaluator map filters`. Pull requests should include a summary, affected role or route, database or environment changes, screenshots for UI changes, and verification commands. Link related issues when available.

## Security & Configuration Tips

- **API routes:** a new route must check the caller with `getApiUser(...roles)` from `@/lib/auth` and return `unauthorized()` when it is null. For report data, also call `canAccessReport`.
- **Page views:** set `roles` on every view and repeat the access checks the page needs. Return only what the page renders, and use `forSender` for report data a sender sees. nginx blocks `/api/views/*` from outside, but write views as if a browser could call them.
- **Pages:** a new page under a portal is protected by that portal's layout and `frontend/proxy.ts`. The backend still decides what data the user gets.

Keep secrets in `.env` (Docker) or `.env.local` (development); these files are ignored and only the backend reads them. Required values:
- `JWT_SECRET` (32 or more characters in production);
- `ARCGIS_PORTAL_URL`, `ARCGIS_DATA_SERVICE_URL`, `ARCGIS_CLIENT_ID`, `ARCGIS_CLIENT_SECRET`, plus `ARCGIS_HTTP_REFERER` when the credential is referrer-restricted;
- in production, `APP_URL` (the public HTTPS site address);
- behind more than one proxy, `TRUST_PROXY_HOPS`.

Do not commit generated build output, `node_modules`, local uploads, or secrets. After changing `backend/src/lib/db/schema.json`, update `shared/db/models.ts` and run `npm run arcgis:provision` (needs a service owner token in `ARCGIS_ADMIN_TOKEN`).
